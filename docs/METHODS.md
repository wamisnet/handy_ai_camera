# 手法の比較と推奨

「どの手法が効くかは試さないと分からない」ため、アプリは 7 手法を同時に走らせて手法別スコアをすべて記録します。
ここでは各手法の性質と、合成画像シミュレーション(`pctools/simulate.py`)から見えた傾向、推奨する初期構成をまとめます。

## 各手法の性質

| 手法 | 何を見るか | 強い変動 | 弱い変動 | 向いている用途 |
|---|---|---|---|---|
| **Shape**(Hu モーメント+アスペクト比+ソリディティ) | 外形シルエット | 回転・スケール・照明すべてに不変 | 外形が同じ製品は区別不可 | 「形が違う製品」のゲート。安価 |
| **Feature**(ORB/AKAZE/SIFT + 比率テスト + RANSAC) | 局所的なコーナー・テクスチャの幾何配置 | 回転・スケール・傾き・部分遮蔽 | 特徴の乏しい面(無地)、強いボケ | **押印文字の違い**、穴・エッジの配置。識別力が最も高い |
| **HOG**(勾配方向ヒストグラムのコサイン) | 全体の見た目の構造 | 小さな位置ずれ、照明 | 180° 曖昧さ(バリアントで対応)、細部の違い | 「全体として似ているか」の粗い判定、登録時の対応付け |
| **NCC**(ECC 整列 → 勾配画像の相関) | 整列後の模様の一致 | 照明(勾配ベース)、数 px のずれ | 傾きが強い、テクスチャノイズ | 押印・刻印などパターンの一致度。ROI と併用で効く |
| **Emboss**(高域強調 → Canny → Chamfer 距離) | エッジの重なり | 輝度差・エッジ太さ・数 px のずれ | 文字の一部だけ違う(寛容すぎる) | 押印の「有無」「大きく違う」の検出。ROI と併用 |
| **Holes**(内側輪郭の点集合照合) | 穴の数・位置・大きさ | 照明・回転・スケール | 穴が背景色と区別しにくい、穴が無い製品 | **金属部品**の穴パターン |
| **Embedding**(TFLite CNN のコサイン) | 意味的な全体特徴 | 照明・多少の形状差・背景ノイズ | 細かい文字・穴の違いには鈍い | 「別カテゴリの物が来た」検出。任意 |

## シミュレーション結果(合成画像)

`pctools/simulate.py` は黒背景 + 押印文字入りウレタン片を 4 製品分合成し、
距離 0.55〜1.6 倍、回転 0〜360°、パース、ガンマ 0.6〜1.6、片側影、ノイズを振った検査画像で各手法を走らせます。
**外形が同じで文字だけ違う**(A-12 / A-13 / A-12X / B-07)という最も厳しい設定です。

```
手法          本人min  本人中央  他者max  他者中央   余裕   判定
Shape        0.971   0.991    0.998   0.990  -0.027  ✗ (外形が同じなので当然)
Feature      0.236   0.361    0.103   0.044  +0.133  ◎ 完全分離
HOG          0.953   0.972    0.980   0.959  -0.026  ✗
NCC          0.333   0.835    0.772   0.503  -0.438  ○ 概ね分離
Emboss       0.642   0.813    0.816   0.671  -0.173  ✗
Emboss+ROI   0.654   0.823    0.814   0.667  -0.160  ○
```

読み取れること:

1. **押印文字の違いを確実に分けられるのは Feature(局所特徴+RANSAC)**。他者は 0.1 以下、本人は 0.24 以上で完全分離。
   スコアの絶対値は低い(0.3 前後)ので、しきい値は 0.15〜0.2 程度に置き、**他製品との余裕**で判定するのが正しい使い方。
2. Shape / HOG は外形が同じ製品には無力だが、**外形が違う製品を弾くゲート**としては有効(値が高くて安定)。
3. NCC / Emboss は文字が違うと中央値では差が出るが、極端な条件(遠距離+強い傾き)で本人スコアが落ちる。
   → 単独では使わず、**融合の一部として重みを持たせ、ROI で押印領域を重視**する。誤りの方向は「本人を NG にする(誤拒否)」側で、誤受入ではない。
4. 実運用ではウレタン製品どうしは外形や大きさも違うことが多いので、Shape/HOG も識別に寄与し、全体としてはシミュレーションより楽になるはず。

## 推奨する初期構成

### ウレタン 2 点セット(押印文字)

| 手法 | 有効 | 重み | しきい値 | 余裕 | gate |
|---|---|---|---|---|---|
| Shape | ○ | 1.0 | 0.6 | 0 | **○** |
| Feature | ○ | **3.0** | 0.15〜0.25 | 0.05 | ○(他製品を登録後) |
| HOG | ○ | 1.0 | 0.55 | 0.03 | - |
| NCC | ○ | 1.5 | 0.35 | 0.05 | - |
| Emboss | ○ | 1.5 | 0.45 | 0.05 | - |
| Holes | - | | | | |

- 検出器は **ORB** から始める(速い)。押印が浅く特徴が出にくければ **AKAZE**(非線形拡散で低コントラストに強い)、最後に SIFT。
- **ROI は必ず引く**(押印文字を囲む、重み ×3)。Feature/HOG/NCC/Emboss すべてが ROI 内を重視する。
- フラッシュシーケンスは OFF→ON 両方。押印の陰影は環境光の斜め成分で出るので **フラッシュなしフレームが効く**ことが多い。
  一方、セグメンテーションにはフラッシュ差分が効く。両方撮って手法側で max を取る設計になっている。

### グレー箱入り金属部品(穴パターン)

| 手法 | 有効 | 重み | しきい値 | 余裕 | gate |
|---|---|---|---|---|---|
| Shape | ○ | 1.0 | 0.6 | 0 | ○ |
| Holes | ○ | **2.5** | 0.7 | 0.1 | ○ |
| Feature | ○ | 2.0 | 0.2 | 0.05 | - |
| HOG | ○ | 1.0 | 0.55 | 0.03 | - |
| NCC | ○ | 1.0 | 0.3 | 0.05 | - |
| Emboss | ○ | 1.0 | 0.4 | 0.05 | - |

- 金属の映り込み(ハイライト)は Feature の偽特徴になるので、フラッシュなしフレームを優先的に見る/AE をやや暗めにするのが有効。
- 箱が何段か積まれた状態・隣に箱がある状態は、箱の内側矩形検出 + 正面視補正で吸収する(既定 ON)。
  合成画像(`pctools/boxsim.py`, 積み重ね・隣接・内壁の影・傾き)では、補正なしで部品と穴が正しく取れたのが 0/30、補正後は 29/30。
  失敗した 1 件は箱が画面の端にかかったケースで、ガイド枠に収める運用で防ぐ。

## しきい値の決め方(運用)

1. 製品を **2 つ以上** 登録し、各パーツに **3〜5 ビュー**(距離・角度違い、フラッシュ有無)を入れる
2. 「手法評価」を実行 → 「余裕」列が正の手法が効いている手法。負の手法は重みを下げる
3. 「推奨しきい値を適用」(推奨値の 95% に置き、余裕は分離幅の 1/3)
4. 実検査を回し、結果画面の「正しい/誤り」を押す
5. `verify_log.csv` を `pctools/analyze_log.py` で見て、**誤受入ゼロを維持したまま誤拒否を減らす方向**にしきい値・重みを調整
6. 新製品追加時は 1→3 を繰り返す(既存製品の余裕が縮んでいないか確認)

## 検討したが採用しなかった/後回しにしたもの

- **OCR(ML Kit 等)**: 押印はコントラストが低く OCR は安定しない上、GMS の無いハンディ端末では動かない。「文字として読む必要はない」要件なので照合ベースにした。
- **製品専用 CNN の学習**: 新製品追加ごとに再学習が要り現場運用に向かない。汎用埋め込み(任意)を最近傍で使う形に留めた。
- **動画**: 連続フレームを使う設計(バースト+中央値集約)で同等の効果が得られる。必要なら framesPerStep を増やせば「短い動画」と同じ。
